# Gestion des fidèles : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** section « Fidèles » (`/fideles`) : ajouter, modifier, supprimer un fidèle, liste paginée, recherche en temps réel tolérante aux fautes.

**Architecture :** module indépendant de la Comptabilité, mêmes couches : règles pures dans `shared/domain/members`, table `members` (migration `0006`), repository + service (index de recherche en mémoire dans le main) + IPC, feature renderer `features/members`.

**Tech Stack :** Electron, better-sqlite3 + Drizzle 0.45, zod, React, TanStack Query, react-hook-form, Vitest, Playwright.

**Spec :** `docs/superpowers/specs/2026-11-27-fideles-design.md` (à lire avant chaque tâche).

## Global Constraints

- Aucun import entre `members` et `accounting` (features, domain, main). Le lint de frontières doit le refuser pour les features ; pour le reste, revue.
- Données de test **toujours fictives** (aucun vrai fidèle dans le repo, public).
- Textes UI en français, sans tiret long ni demi-tiret ; dates affichées `fr-FR`.
- Nom : MAJUSCULES `fr-FR`. Prénom : `rAkoto TiaNa` → `Rakoto Tiana`, `jean-pierre` → `Jean-Pierre`.
- Téléphone stocké `+261XXXXXXXXX`, affiché `034 12 345 67` ; 9 chiffres significatifs commençant par 2 ou 3.
- Obligatoires : nom, prénom, date de naissance (1900-01-01 à aujourd'hui), adresse.
- Communiant ⇒ baptisé (formulaire, service `BUSINESS_RULE`, CHECK SQL).
- Matricule unique parmi les fidèles actifs, insensible à la casse, bloquant (`CONFLICT`).
- Doublon probable (même nom, prénom, date de naissance) : avertir, `CONFLICT` tant que `confirmDuplicate` est faux.
- Suppression douce. Horloge injectée, jamais `new Date()` dans un service.
- 50 fidèles par page, debounce 200 ms, recherche < 100 ms côté main.
- Pas de nouvelle dépendance npm.
- Mémoire du porteur : la **suite complète** (`npm run lint && npm run typecheck && npm test`) une seule fois juste avant chaque commit ; pendant la tâche, seulement les tests ciblés.

## Review Focus

1. Recherche faite seulement d'espaces ou de ponctuation (`"  - "`) : traitée comme vide (liste complète), pas de résultat vide ni d'erreur. Test : Tâche 2.
2. Modifier un fidèle sans changer son matricule ni son identité : ni « matricule déjà attribué », ni « doublon » contre lui-même. Test : Tâche 5.
3. Supprimer le seul fidèle de la dernière page : l'écran revient à la page précédente au lieu d'afficher une page vide. Test : Tâche 7.
4. Taper une recherche en étant page 3 : retour en page 1. Test : Tâche 7.
5. Téléphone saisi sans 0 ni indicatif (`341234567`), ou avec espaces, points, tirets (`034.12.345.67`) : accepté et normalisé. Test : Tâche 1.

### Task 2 : recherche approchée (fonction pure)

**Files :**
- Create : `src/shared/domain/members/members.search.ts`, `members.search.test.ts`, `__golden__/search.json`

**Interfaces :**
- Produces :
  - `interface SearchEntry { id: number; lastName: string; firstName: string; registrationNumber: string | null }`
  - `normalizeForSearch(text: string): string` (minuscules, accents retirés via NFD, toute ponctuation → espace, espaces réduits)
  - `type SearchIndex` (opaque : entrées pré-normalisées, triées nom puis prénom avec `localeCompare(…, 'fr')`)
  - `buildSearchIndex(rows: readonly SearchEntry[]): SearchIndex`
  - `searchMembers(index: SearchIndex, query: string): number[]` (ids classés ; requête normalisée vide → `[]` et l'appelant traite comme « pas de recherche »)
  - `isBlankQuery(query: string): boolean`

Algorithme (pas déterminé par les tests seuls) :

```
mots du fidèle = mots(normalize(nom)) ∪ mots(normalize(prénom))
pour chaque mot tapé t, score(t) = min sur les mots w :
  0 si t == w ; 1 si w commence par t ; 2 si |t| ≥ 3 et w contient t ;
  sinon si |t| ≥ 4 : d = min(DL(t, w), DL(t, w[0:|t|])) ; max = |t| ≥ 8 ? 2 : 1 ; d ≤ max → 3 + d
matricule m = normalize(matricule) sans espaces : t == m → 0, m commence par t → 1, |t| ≥ 2 et m contient t → 2
un mot tapé sans score → fidèle exclu ; score total = somme ; tri : score croissant puis ordre de l'index
DL = Damerau-Levenshtein (transposition adjacente), arrêt anticipé au-delà de max
```
